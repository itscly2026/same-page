# Same Page

> 当前状态：开发阶段，已有线上版本。下文默认描述当前实现；待实现能力单独标注。合并、部署成功和真实设备验收是不同证据，最新上线状态以对应 PR 的发布记录为准。

Same Page 是一款面向合唱排练的乐谱 PWA。它让成员围绕同一份 PDF 乐谱工作，通过共享批注层传达排练要求，并通过个人层保留自己的记号。

产品使用同一套响应式 Web/PWA 界面服务平板、桌面和手机，主要使用环境在中国大陆。Cloudflare 国际版的偶发网络不稳定是首版接受的限制，离线能力不得因此被夸大成永久存储保证。

## 核心验收故事

V1 必须完整跑通以下路径：

1. 管理员上传一份 PDF，验证通过后它立即出现在云盘文件库中。
2. 获授权编辑者在共享层添加批注。
3. 成员下载离线副本，查看共享批注并在个人层编辑。
4. 草稿可靠写入本机后，在浏览器仍保留站点数据的前提下，断网、刷新或关闭应用可恢复草稿；清除站点数据、存储驱逐或设备损坏不在此保证内。
5. 恢复网络后，本机待上传操作可靠同步。
6. 不同批注对象的并发修改自动合并；同一对象的后到修改成为提交设备上的本地冲突。

V1 不包含实时协作、WebSocket、自动批注迁移、导出、打印、演出单、文件夹、标签、公开创建云盘、计费或端到端加密。

## 云盘与加入方式

数据模型从第一天支持多个互相隔离的云盘，一个用户可以加入多个云盘；产品入口只按云盘划分，不提供跨云盘乐谱、收藏或动态聚合。

首版不开放创建或关闭云盘的产品入口。部署时预置 **小红花云盘** 及其首位管理员，未来新云盘由平台运维命令创建。

每个云盘选择一种访客准入方式：邀请准入或开放准入。两种方式只改变访客如何进入，
进入后使用完全相同的云盘、乐谱、批注与权限路径：

- 邀请准入使用八位邀请码；邀请码由不易混淆的大写字母和数字组成，同一时间只有一个
  有效值，管理员可以轮换。
- 开放准入允许访客通过该云盘的专属链接直接进入，不需要邀请码；全站首页不提供公开云盘目录或搜索。
- 产品可以把一个开放准入云盘配置为唯一的“公开体验”入口。该入口只向未登录访客展示；登录不会把体验访问升级为成员关系，已登录非成员也不会收到加入提示。它是产品发现入口，不是一种新的云盘或准入类型。
- 未注册访客读取当前文件库中的乐谱和全部共享层，不形成成员关系，也不出现在成员列表中。
- 访客可以下载离线副本，但已经下载的内容无法远程追回。
- 邀请或普通开放准入访客通过邮箱注册、Google 或微信完成认证后，再填写云盘内显示名并建立普通成员关系；公开体验访客除外。
- 已注册用户可以按目标云盘的访客准入方式加入多个云盘。

## 身份、成员与权限

Same Page 的认证首屏以邮箱为主入口：用户先输入邮箱，服务端受限地返回登录或注册流程；该产品取舍会暴露邮箱是否已注册，因此接口只返回流程类型，并按 IP 与规范化邮箱限流。注册时使用一次邮箱 OTP 确认邮箱归属，日常使用密码登录，忘记密码时也使用邮箱 OTP 安全重置。主表单下方提供 Google 与微信图标入口；只有对应的一整对生产凭据存在时才显示，任一配置缺失都会隐藏该入口。

Google 使用其已验证邮箱；Better Auth 只在安全确认相同邮箱时复用现有用户。不同邮箱不会被推断为同一人，也不提供手工合并、绑定或解绑。微信网站应用登录优先使用 `unionid`，否则使用该应用命名空间内的 `openid`；微信不提供邮箱时生成不可投递的内部占位地址，该地址不得用于 OTP、密码重置或联系用户。所有登录方式完成后复用同一套访客续接、公开体验退出和云盘内显示名流程。

认证由 Same Page 自己的 Better Auth/D1 边界负责；OAuth access token 与 refresh token 加密后保存，完成身份验证后不持久化 Google ID token。认证邮件通过独立的 Resend Sending-only key 和发送域发出，不调用或共享现有 Webmail 的 API、Secret 或 Sent 数据。

公开隐私政策固定发布在 `/privacy`，首页底部提供入口；第三方登录平台应使用该生产 URL，
不得指向仓库文档或未发布的临时页面。

权限只在所属云盘内生效：

- **云盘管理员**：查看成员、管理乐谱与邀请码、查看用量，并设置固定共享层的默认颜色和编辑权；成员移除等生命周期流程见 #97。
- **共享层编辑权**：允许某个成员关系编辑指定共享层，同一层可授权给多人。
- **普通成员**：读取全部共享层，编辑自己的个人层。
- **访客**：读取当前文件库中的乐谱与共享层，不能修改云端数据。

“指挥”“声部长”和声部名称不是写死的系统角色。每份乐谱固定包含 E/S/A/T/B 共享层；管理员不能创建、重命名、删除或排序共享层。编辑授权以云盘和槽位为边界，对云盘内全部乐谱生效。

同一个用户在不同云盘可以使用不同的云盘内显示名。只有管理员可以查看成员名单和登录邮箱；普通成员与访客没有成员目录。共享批注保留创建者和最后修改者的云盘内显示名，只有管理员和共享层编辑者在对象详情或冲突场景中看到署名。

**生命周期目标，尚未完成（#97）**：删除用户将立即停止登录，身份数据和个人层进入三十天恢复期；成员退出或移除将立即撤销云端访问，服务端个人层同样保留三十天。恢复期结束后删除个人数据，共享批注保留最终云盘内显示名。目前不要把上述目标理解为已提供自助入口或已运行自动清理；涉及实际删除请求应联系运营者确认处理范围与安排。

## 乐谱与文件

一份乐谱属于且只属于一个云盘。文件库直接使用上传 PDF 的文件名，不要求另填标题、
作曲者或编曲者，也没有草稿与发布状态。管理员可以重命名；当前文件库中的文件名按
Unicode 规范化后忽略大小写唯一。文件按中文自然顺序排列，搜索只匹配文件名；V1
不做文件夹、标签、收藏、手工排序或跨云盘搜索。

文件规则：

- 只接受 PDF，单份最大 **20 MB**。
- 每个云盘的全部文件对象共享 **1 GB** 配额。
- 当前、回收站和保留期内的历史 PDF 版本都计入配额。
- 当前检查大小、文档加载及首尾页，检查中发现的加密、损坏或无法解析的文件会被拒绝；不保证所有中间页都可解析或渲染。全页验证仍待 #97。
- 上传只选择一个或多个 PDF；每个文件独立验证，单个失败不影响其他文件。
- 验证、对象写入和数据库提交全部完成后，文件才会原子地出现在文件库中。

PDF 替换不会尝试理解内容或迁移批注：

- 每次替换生成新的不可变 PDF 版本，并更新乐谱的当前版本指针。
- 现有批注继续按原页码和归一化坐标显示；当前替换操作不提供叠加预览，替换前预览与确认流程待 #97。
- 页数减少时，超出范围的批注保留但不可见。
- 离线用户可以继续使用旧版本；进入乐谱或手动同步时提示新版本。
- 新版本完整下载并校验成功后才切换本地副本。
- 旧 PDF 保留三十天后清理；历史版本列表与用户可用的回滚流程待 #97，不能把“文件仍保留”当作“回滚功能已完成”。

删除采用仅管理员可用的回收站：

- 删除后乐谱立即从成员与访客的文件库和云端同步路径消失。
- 回收站保留乐谱身份、全部 PDF 版本和批注三十天，只提供恢复，不提供立即永久删除。
- 回收站中的同名文件不阻止重新上传；恢复发生同名冲突时，管理员必须先为待恢复文件重命名。
- 已下载的离线副本和本机未同步批注不会被远程抹除，但回收期间停止编辑与同步；乐谱恢复后继续同步。
- 到期后定时任务自动永久删除乐谱、PDF 版本与批注，并回收对应对象存储。

## 阅读器

V1 同时支持：

- 翻页模式：每次只显示当前一页，通过上一页、下一页、左右滑动或键盘切换页面。
- 连续滚动模式：多页纵向排列并按视口虚拟化 PDF 页面。

两种模式共享同一页坐标和批注数据，用户可以随时切换，并按用户、按乐谱记住选择。阅读器支持缩放、拖动、触摸/鼠标/键盘翻页、页码输入和缩略图导航。

在线阅读使用 HTTP Range。离线副本要求 PDF、批注和必要资源完整保存在本机；仅打开过乐谱或命中缓存不代表可离线使用。每份本机工作区都绑定不含邮箱的稳定 `ownerKey`，并按 owner、云盘和乐谱隔离；完整离线快照不会跨登录用户复用。PWA 安装是建议，不是使用门槛，也不防止浏览器清理站点数据。

## 批注层与工具

打开乐谱时默认进入阅读模式。在阅读模式中：

- 翻页模式下，左右滑动或拖动只用于切换页面。
- 连续滚动模式下，上下滑动或拖动只用于滚动页面。
- 点击、拖动、触摸或手写笔输入都不能创建或修改批注。

有编辑权限的用户必须明确点击“编辑”才能进入编辑模式。每次进入编辑模式都默认选择文本工具；用户点击谱面位置后才创建文本输入框。只有再次选择画笔工具后，拖动才会产生笔迹。编辑模式沿用阅读器顶部控制，只将编辑按钮显示为黑底白图标；再次点击该按钮退出编辑模式并恢复阅读手势。

每份乐谱固定有 E · Ensemble、S · Soprano、A · Alto、T · Tenor、B · Bass 五个共享层，以及每名用户唯一的 P · Personal 个人层。

- 管理员在云盘级设置共享层默认颜色和编辑授权，不改变槽位名称或顺序。
- 成员和访客可以读取共享层；阅读模式按有效订阅显示共享层，个人层始终显示。订阅只影响显示，不授予编辑权。
- 订阅优先取谱子级覆盖，再取用户的云盘默认；颜色优先取用户的云盘覆盖，再取管理员默认和产品默认，不提供谱子级颜色覆盖。用户偏好跨设备同步，访客偏好仅在当前设备保存。
- 编辑模式忽略订阅，只显示当前选中的可编辑层；选择未订阅的层编辑不会修改阅读偏好。
- 任何拥有该层编辑权的成员都可以修改或删除层内任意对象。
- 个人层只允许本人通过产品 API 读取和编辑；V1 采用应用级权限隔离，不做端到端加密。

V1 工具：

- 文本：新增、编辑、移动和删除。
- 画笔：支持鼠标、触摸和手写笔，固定线宽为基线，可在设备支持时记录压感。
- 橡皮：整条删除笔迹。
- 撤销/重做：只作用于当前层和当前编辑会话。

V1 不做形状、荧光笔、套索、多选、图片、激光笔或单对象自定义颜色。

## 本地保存与同步

批注对象是一条具有稳定 ID 的笔迹或文本。绘制期间的修改持续写入 IndexedDB，用户点击“完成”时批量提交：

- 在线无冲突：显示已同步。
- 离线：显示已保存到本机和待同步数量。
- 当前登录身份解析完成、网络恢复或应用恢复前台时：应用壳对该 owner 的多份乐谱执行有界 outbox 扫描；逐份核对云端状态和访问权限，只 push，不 pull。
- 进入乐谱或点击“立即同步”时：执行 push 和 pull。
- 不后台轮询其他成员的新批注，不使用实时连接。

每个同步操作包含稳定 `opId`、`annotationId`、`baseVersion`、操作类型和 payload。D1 使用乐观并发控制：

- 不同对象的操作独立接受并自动合并。
- 同一对象版本已变化时，服务端保留已接受版本并拒绝后到操作。
- 被拒绝的版本只留在提交设备，成为本地冲突，不上传云端，也不向其他编辑者展示。
- 提交者可以放弃本地版本、基于当前版本重新应用，或将两份内容保留为两个对象。
- 同一批提交里的非冲突操作照常成功。
- `opId` 唯一约束保证丢失响应后的重试不会产生重复对象。

退出登录或清理离线数据前，未同步操作和本地冲突必须被明确处理或确认丢弃。浏览器数据被清理或设备损坏导致的本地冲突丢失，是 V1 明确接受的限制。

会话自然过期不阻止最后登录用户继续访问其本机离线数据，但恢复同步必须由同一用户重新认证。若同一浏览器登录了另一用户，旧工作区立即停止显示、编辑和同步。访客使用独立的设备本地随机 owner，不会静默提升为注册用户的私有工作区。主动退出登录会在警告后清除本机私有数据和权限信息，并把仍可保留的已同步共享内容转换到新的访客工作区。

## 当前技术边界

当前实现栈：

```text
React + TypeScript + Vite
├── PDF.js：PDF Range、解析、页面渲染和虚拟化
├── SVG overlay + DOM：V1 批注显示与编辑
├── React Aria Components：跨输入方式与无障碍组件
├── Dexie：IndexedDB、本地草稿、outbox、冲突与偏好
├── vite-plugin-pwa：manifest、应用壳和更新流程
└── Zod：客户端、API 和 operation 边界校验
                │
                │ 同源 HTTPS
                ▼
Cloudflare Worker + Hono
├── Better Auth：密码、注册/重置 OTP 与会话
├── D1：云盘、成员关系、权限、乐谱元数据、批注对象和同步记录
├── R2：不可变 PDF 版本对象
└── Resend：独立 Same Page 认证邮件边界
```

PDF 批注的领域数据不得使用绘图库序列化格式。SVG 必须通过真实高密度笔迹原型；只有它在目标设备上无法达标时才采用 `react-konva`。Workbox Background Sync 只能作为增强能力，不能替代业务 outbox。

## 工程开发

工程使用 Node.js 24 与 npm。Cloudflare Vite plugin 在同一个开发和构建流程中运行 React 客户端、Workers Static Assets 与 Hono API；`/api/*` 先进入 Worker，其余未知路径回退到 React SPA。

```bash
npm ci
npm run dev          # React + Worker 本地开发
npm run lint         # ESLint
npm run typecheck    # 客户端、配置与 Worker 类型检查
npm run test         # React/Vitest 单元测试
npm run test:worker  # workerd 内的 Worker 测试
npm run build        # 类型检查与生产构建
npm run check        # 常规集合，已包含视觉浏览器测试，详见下方
npm run check:full   # 与 CI verify 相同的检查集合（非部署）
```

`check` 包含 lint、类型检查、客户端、Worker、视觉浏览器测试、迁移测试与生产构建；它不是纯单元测试的快速入口。`check:full` 在此基础上增加真实 PWA 更新交接与加载性能检查。CI 保持逐步骤执行同一完整集合，便于定位失败；两者执行顺序不必相同。单独的 `npm run test` 可用于较快的客户端反馈。

视觉浏览器测试文件串行执行，避免各自启动的 Vite/workerd 争用调试端口及同一工作目录下的本地 SQLite；没有跳过测试用例。

首次运行任何含浏览器的集合前，先安装两个引擎：

```bash
npx playwright install chromium webkit
# Linux / CI 还需系统依赖：npx playwright install --with-deps chromium webkit
npm run check:full
```

依赖与浏览器首次安装需要网络和磁盘空间。完整检查会启动本地 workerd/Vite、临时 D1 与浏览器，并多次构建，通常需要数分钟；不需要生产凭据，也不对生产数据执行迁移。`check:full` 不能与其他构建命令在同一工作目录并行运行。它不生成完整视觉报告，也不执行部署或真实设备验收；生成报告另用 `visual:report`。发布后另外运行 `verify:deployment`，实机与邮件验收单独记录。

### iPad 视觉报告

视觉报告直接运行当前生产构建中的 React 路由、样式、PDF.js 阅读器和交互实现，
再由 Playwright 在浏览器请求层提供固定的虚构会话、云盘、权限、PDF、图层和批注。
它不需要真实账号、邀请码、D1、R2 或私人乐谱，也不维护第二套产品页面。

报告使用 Chromium；同时安装 WebKit 以运行仓库的其他浏览器门禁：

```bash
npx playwright install chromium webkit
npm run visual:report
```

报告固定生成到 `artifacts/visual-report/index.html`，PNG 位于其
`screenshots/` 目录，`manifest.json` 记录 commit、场景、App viewport 和实际 PNG
像素尺寸。每次运行会替换这个忽略提交的生成目录。

场景清单位于 `visual-report/scenarios.mjs`。新增场景时应只声明当前路由、虚构身份、
iPad 方向、稳定完成条件和必要的用户操作；请求数据统一由
`visual-report/fixtures.mjs` 提供。未声明的 `/api/*` 请求会直接返回 404，防止报告意外
访问本地或生产业务数据。

这里的 iPad 是确定性的浏览器设备仿真，适合检查当前 Web UI 和生成视觉报告；它不证明
真实 iPad Safari 浏览器工具栏、虚拟键盘、PWA 全屏、安全区、Apple Pencil 或实体设备
交互。真实设备验收仍按 production release runbook 独立记录。

Reader 路由和 PDF.js 从首页 bundle 中拆出；进入云盘后，浏览器仅在空闲时预载
Reader 路由和 PDF.js worker，不提前请求任何乐谱 PDF。PWA 只由
`vite-plugin-pwa` 生成并注册一个 Service Worker，更新通过页面提示由用户确认。
生产资源、发布流程和实机门槛见
[production release runbook](./docs/operations/production-release.md)。

### 本地身份与云盘初始化

将 `.dev.vars.example` 复制为不会提交的 `.dev.vars`，并为
`BETTER_AUTH_SECRET` 与 `INVITE_SECRET` 分别设置至少 32 个字符的独立随机值。
Resend key 只用于 Same Page 的注册及密码重置邮件，不与其他邮件系统共用。应用日志不得记录
OTP、收件人、邮件正文、邀请码或认证 Secret。

Google 与微信登录是可选配置。分别同时设置 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
和 `WECHAT_CLIENT_ID` / `WECHAT_CLIENT_SECRET` 才会启用对应入口；不要提交这些值。

```bash
npm run db:migrate:local
npm run dev
```

首位管理员需要先在页面设置密码并完成一次邮箱 OTP 注册。随后由运维人员在进程环境中提供
`INVITE_SECRET`，创建默认的“小红花云盘”及管理员关系：

```bash
INVITE_SECRET='与 .dev.vars 相同的独立值' npm run provision:choir -- \
  --admin-email admin@example.com \
  --admin-display-name 管理员 \
  --local
```

命令默认只操作本地 D1；生产执行必须显式传入 `--remote`。为避免邀请码进入自动化输出，
命令默认不显示初始邀请码；管理员首次登录后在云盘页面轮换并立即通过私密渠道发送。只有
人工直接运行且确实需要即时交付时，才显式传入 `--show-join-code`，原码不得粘贴到 Issue、
PR、日志或长期存档。产品和公开 API 均不提供创建云盘入口；新增云盘沿用同一个受控运维命令。

采用开放准入的云盘也使用同一个命令创建，只增加准入参数：

```bash
INVITE_SECRET='与 .dev.vars 相同的独立值' npm run provision:choir -- \
  --admin-email admin@example.com \
  --admin-display-name 管理员 \
  --choir-name 公开体验云盘 \
  --guest-admission open \
  --preview-entry \
  --local
```

`--preview-entry` 只能与 `--guest-admission open` 一起使用；数据库最多允许一个云盘承担该入口。运行迁移前已经存在的开放准入云盘不会被名称自动识别，需要通过受控 SQL 将目标行的 `is_preview_entry` 设为 `1`。

Better Auth 的数据库定义由官方 CLI 生成。认证配置发生模型变化时运行
`npm run auth:schema` 并审查生成结果；D1 的实际变更仍通过 `migrations/` 中的迁移执行。
生产 D1/R2/Worker/Resend 绑定和 QQ、163、Gmail、Outlook 投递验收属于 Issue #9，
不能用本地自动化结果替代。

### 乐谱文件与本地阅读器

本地开发时 `SCORES_BUCKET` 使用 Wrangler 的本地 R2；生产桶仍由部署环境显式绑定。
上传 API 会先用面向 serverless 环境的 `unpdf`/PDF.js 解析副本，再把原始字节按不可变
版本写入 R2。D1 通过云盘用量字段和触发器原子阻止并发超额，不能用客户端展示的用量
代替服务端配额检查。

替换 PDF 会锁定单份乐谱的版本推进，创建新对象后才切换当前版本；旧版本设置三十天
保留期。定时任务永久删除到期的回收站乐谱，再回收过期旧版、中断超过一小时的待上传
版本和删除队列中的 R2 对象。所有当前、回收站、待清理历史版本和待完成上传都计入云盘
1 GB 配额。

客户端 PDF.js 只在阅读器路由加载。连续滚动及缩略图列表复用 TanStack Virtual，页面
画布和后续批注层共同使用页码与归一化页面坐标。离线下载使用明确的版本 URL，并在
SHA-256 完整校验后通过一次 IndexedDB 事务切换本地活动版本；下载或校验失败不会覆盖
已有离线副本。PDF.js worker 属于 PWA 必要资源，已纳入应用壳预缓存。

### 批注与对象级同步

批注显示与编辑使用 SVG overlay 和 DOM 文本输入，不采用绘图库私有序列化格式。阅读
模式下 overlay 不接收指针事件；显式进入编辑后默认文本工具，画笔才会接收拖动，橡皮
按稳定对象 ID 删除整条笔迹。文本、笔迹和压感点均保存为页码加归一化页坐标，同一份
数据可在翻页与连续滚动布局中复用。

Dexie 通过统一的 Local Workspace interface 保存本地对象、编辑草稿、outbox、冲突、拉取游标、图层缓存、同步租约、离线快照和访客偏好；所有可变状态都按 `ownerKey + choirId + scoreId` 隔离，调用方不自行拼接存储 key。
`dexie-react-hooks` 只负责把 IndexedDB 变化接入 React。完成编辑时才把草稿编成稳定
`opId` 操作；同一对象的本机操作严格串行，不同对象仍可同批提交。应用级 Coordinator
只扫描当前 owner，并在启动、网络恢复、前台恢复或用户明确同步时有界 drain 多份乐谱的
outbox；回收站、权限撤销、会话失效和暂时不可用会停止对应乐谱并保留本机操作，一份失败
不阻塞其他乐谱。进入乐谱和“立即同步”才执行 push 与 pull。Web Locks 协调多标签页，
不支持时使用带过期时间的 Dexie 租约。

D1 为每个对象执行独立 OCC：`baseVersion` 命中才接受并推进版本，否则返回当前规范
对象。被拒 payload 不写入云端批注，也不保留在服务端幂等日志；服务端只保存其
SHA-256 指纹来识别相同 `opId` 的响应丢失重试。本机把被拒版本保存为本地冲突，用户
可以放弃、基于云端版本重做，或以新对象同时保留两份。共享层编辑权、个人层所有权、
跨云盘边界和署名可见性都在服务端校验；普通成员与访客读取共享对象时不获得署名。

## 持续验证与人工门槛

以下能力已有相应实现或自动化，但仍需按变更风险持续验证，不能将其视为全部已通过实机验收：

1. PDF.js + R2 鉴权 Range、连续滚动虚拟化、DPR 与内存回落。
2. 当前 SVG 批注在高密度笔迹、缩放、整条删除和多层显示下的实机表现；`react-konva` 不是已采用的实现。
3. D1 对不同对象合并、同对象冲突、重复 `opId` 和游标推进的原子性。
4. 断网、强杀、重启、多标签页、会话过期和恢复同步。
5. 20 MB PDF 的完整下载、校验、缓存替换和存储回收。
6. iPad Safari、Android 平板和桌面浏览器上的真实手写与手势。
7. QQ、163、Gmail 和 Outlook 的注册/密码重置 OTP 投递及延迟。

自动化使用 Vitest、React Testing Library、Cloudflare Vitest 插件和 Playwright。Playwright WebKit 不能替代真实 Safari；PWA、Service Worker、存储驱逐和手写笔必须保留人工实机验收。
