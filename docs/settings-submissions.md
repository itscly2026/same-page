# 设置提交

Issue #244 将成员与权限、共享层管理、共享层配置及用户生命周期的提交时序集中到 `src/client/settings/settings-mutation.ts`。`useSettingsMutation` 的 interface 是调用方和测试共同使用的 seam；HTTP 结果分类留在 implementation 内，不再由页面分别解释。

## 职责

调用方提供当前是否允许操作、重新读取当前状态的方法，以及失权时清除授权内容的动作。每次提交只提供请求及必要的已确认写入处理；成员权限草稿清理、共享层 availability 投影和用户删除后的本机归属处理仍在各自领域。

module 用同一个同步门闩管理提交和恢复读取，在 React 更新 pending 之前也能拒绝第二次写入。它必须放在按用户及云盘（需要时再加共享层槽位）设置 key 的视图内；卸载后旧请求不能执行领域回调、刷新或发布反馈。领域回调自身跨越异步步骤时，用传入的 `isCurrent` 检查后续副作用；本机事务继续检查原有 owner/session。

HTTP 成功是写入确认点。领域处理或重新读取随后失败，仍显示“已保存，但刷新失败”，并只提供读取恢复；不重放写入或已确认回调。正常成功静默，用户生命周期可以保留自己的完成提示和跳转。退出确认框消费相同的提交反馈及禁用状态，已确认写入后的刷新失败不能再次显示成“保存尚未确认”或允许重复发送。

| 结果 | 后续行为 |
| --- | --- |
| 写入及后续处理成功 | 结束 pending，正常继续 |
| 写入已确认，后续处理失败 | 保留确认，重新读取前禁止再次提交 |
| 传输失败，结果未确认 | 保留输入，先由用户重新读取确认状态 |
| 401 / 403 | 清除已确认授权内容，重新读取前禁止提交 |
| 409 | 保留修改，重新读取后由用户核对 |
| 其它拒绝 | 保留修改，允许修正后重试 |

`submit` 返回 `true` 表示写入和后续处理均成功，`false` 表示当前提交未完整完成，`null` 表示未开始提交或结果已过期。这个返回值用于退出确认及关闭当前对话框；是否已写入由 module 的反馈表达，调用方不再分类状态码。

共享层详情复用 `useReadResource` 区分已显示内容与已确认操作能力。刷新不卸载表单；新内容更新未修改的表单，有修改的表单保留输入。读取缓存不会授予配置能力。

## 验证入口

- `src/client/settings/settings-mutation.test.tsx`：同步重入、延迟响应、异步领域回调、失权、冲突与仅重新读取的恢复流程。
- `src/client/routes/shared-layer-details-page.test.tsx`：保存后刷新失败、冲突草稿保留及暖读取更新。
- 原有成员权限、共享层管理、用户生命周期与 `app.test.tsx`：继续验证权限、退出、草稿和离线共享层投影；响应丢失分支明确执行重新读取后再恢复共享层。
- Chromium/WebKit 的设置、导航与层管理场景继续验证实际交互；受控请求测试不代表真实设备或生产部署验证。
