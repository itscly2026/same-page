# 云盘文件库 module

`DriveLibrary` 是文件库的测试面与页面调用入口。它统一处理首次进入、联网刷新、成员加入、乐谱变更后的重新确认，以及本机搜索、排序和返回位置。

## 职责

- `drive-library.ts`：以一个生命周期持有访问结果、可见乐谱和本机视图；合并正在进行的普通刷新，变更后取代旧请求，忽略过期结果。它只在有效所有者与有效请求下写入缓存。
- `drive-library-transport.ts`：生产网络 adapter，使用 bootstrap 提供一致的内容、成员关系与管理权限；只在首次进入或重新打开时执行必要的访客准入。测试 adapter 可以控制结果先后与失败。
- `drive-library-cache.ts`：有容量上限的内容和云盘摘要缓存，包含所有者取消信号；切换所有者或显式清除时取消此前所有工作。缓存不是授权依据。
- `library-view-state.ts`：本机搜索、排序、返回位置和最近打开记录。内容缓存不再复制视图字段，文件库是视图写入的唯一调用入口。
- `use-drive-library.ts`：React adapter，订阅 snapshot、连接焦点/联网/滚动事件，并在文件列表提交后执行一次返回位置恢复。
- `choir-page.tsx`：展示状态、菜单和文件操作，记录阅读器打开性能并预备乐谱摘要；不编排网络与缓存，也不直接保存视图。

## 可观察规则

1. 本机缓存可以先显示，但不形成成员关系，也不恢复管理权限；当前联网结果才能确认这两项事实。
2. 暂时不可用时保留可见内容；明确失权、不存在或需要重新加入时移除当前云盘缓存。
3. 普通刷新共享一个请求。变更后的刷新使旧请求失效；即使 adapter 忽略取消，旧结果也不能覆盖新状态。所有者切换、显式清除和生命周期结束同样阻止迟到写入。
4. 搜索与排序在请求等待期间仍可修改。滚动位置由文件库私有保存，滚动事件不重新过滤整份文件库，也不触发页面重绘。
5. 返回位置只在首个可见列表提交后恢复一次。背景刷新不再次恢复旧位置；等待恢复时的浏览器初始滚动事件不覆盖目标位置。

`DriveLibrary` 的取消负责阻止后续本机结果与请求；它不撤销已经到达服务端的加入或访客准入操作。

## 验证

`drive-library.test.ts` 通过同一 interface 和真实本机视图存储检查请求竞争、所有者隔离、失权、失败、恢复与加入；`app.test.tsx` 保留访问入口和列表提交后的 DOM 滚动验证。`drive-library-lifecycle.test.mjs` 在 Chromium/WebKit 检查缓存返回、权限恢复、背景刷新、搜索排序与失败重试。`drive-entry-library.test.mjs` 继续检查紧凑布局、44px 目标、键盘操作与离线副本流程。

依据 Issue #150；遵守 ADR-0004、0010、0011。文件库缓存和经过完整校验的离线副本是不同事实。
