# Use a content-first single-page reader shell

Same Page will use an iPad-first reader in which the score is the sole primary content: a score first opens in 翻页模式 fitted to one whole page in every orientation, while 连续滚动模式 remains an optional per-score preference, and all reader chrome stays hidden until a central tap after a one-time first-use hint. In 阅读模式, edge taps or horizontal swipes turn pages, pinch and drag zoom or pan, a page turn restores whole-page fit, the last page and layout are restored on the same device only, and thumbnails, layers, layout, offline, and synchronization controls appear in overlay panels; only a new PDF version, a local conflict, or local-data risk may interrupt the score. 编辑模式 focuses and locks the current page—even when entered from 连续滚动模式—and keeps the revealed top controls in place with only the edit control shown as selected; toggling that control off restores the previous reading layout and position. Always-visible reading chrome, reflowing sidebars, two-page spreads, cross-device reading-position sync, and editing across pages are deliberately excluded because they dilute score focus or add complexity to the first version.

Entering or leaving editing preserves the current page's scale and viewport position. In continuous reading, editing hides and disables neighbouring pages while retaining the existing page geometry and scroll container; rebuilding a fitted single-page layout would lose the user's place. Finishing reveals the same reading layout without a scale conversion or scroll restoration.

Reading is immersive by hiding application controls. A supported browser exposes full-screen reading through a user gesture, requesting hidden navigation UI on the document root so body portals remain visible. Leaving the reader exits only the fullscreen session it requested; unsupported platforms keep ordinary reading. The background fills the viewport, while the score viewport fills that background and controls respect device safe areas. Safe-area insets must not crop the zoomed score viewport. Browser and installed-app policies retain authority over system status bars.

Module loading, local identity preparation, document loading and first paint share the content-first paper shell. Retry and diagnostics appear only on failure. Returning first closes the top overlay, then commits composing text and awaits durable local editing before leaving editing; an explicit internal link continues to its destination after these steps. Cloud synchronization does not hold navigation.

The open deadline includes source selection, document readiness and first visible page confirmation. A PDF.js document resolving is not proof that the loading overlay has disappeared. Only the current document's display callback confirms presentation; an unpainted document is never retained as a successful recovery target. Timeout provides retry/back navigation and safe stage diagnostics, without classifying the device as incompatible. Local Blob reads are bounded so stalled storage does not occupy verification slots indefinitely; online source arbitration remains independent of annotation synchronization.

In continuous reading, the page at the vertical viewport center is the current page used by editing and preview selection; a trailing fragment at the top does not determine it. Revealing reading controls also reveals the compact horizontal thumbnail strip and a separate translucent page-position capsule. The thumbnail strip is a centered whole-document scrubber that shrinks to its page count, capped by the available width: resting thumbnails are sampled to fit the available width without overlap, the selected thumbnail enlarges in place, and dragging maps directly to a page, and a native range input provides touch and keyboard access. Page labels update immediately; a 120ms pause or release selects the latest destination without queueing intermediate renders. At most 40 thumbnails are sampled at a minimum 14px spacing, while every page remains selectable. The strip uses half-height miniature pages and a 50% translucent white background. The page-position capsule sits separately at the upper right; the bottom strip has no page labels, selection outline, or floating preview card.

Continuous reading initially fits width. The explicit “适合页面” action fits the current page in both dimensions and realigns it after geometry changes. Editing keeps the current page mounted and locked, allows two-finger pan/zoom, and cancels the interrupted single-touch edit when the second finger takes over; it cannot turn pages. Erasing is previewed until release so navigation cancellation does not delete ink. Text composition has its own commit state: saving another annotation cannot disable a newly mounted textarea and prevent its user-gesture autofocus. A pending text commit makes the input read-only instead of disabling it, preserving focus and the draft on failure. Native software keyboard behavior still requires device acceptance.

The public preview score link explicitly requests local experience, including when the browser has an authenticated session. Experience reads omit account layers and never provision a server personal layer. Signed-in experience data has a separate local owner scope tied to that account's existing session fence; guest experience uses the existing per-drive guest scope. Notes stay durable in local storage, never enter the outbox, are not uploaded or migrated at login, and clearing a score's experience notes also removes its offline snapshot copies. Explicit logout clears the signed-in experience's private and mutable local data together with account data; only sanitized public offline copies may remain. Ordinary member reader links retain their account workspace. The source drive's permission and shared-layer information remains readable through its existing access rules.

The last explicitly selected note tool is a local preference scoped to the same owner as tool styles. It is retained across scores and reloads, with text as the fallback for missing, invalid or unreadable preferences. Choosing a tool is sufficient to remember it; entering editing does not overwrite it. Opening a score still starts in reading mode. Text composition retains its accessible name and user-gesture focus without a visible placeholder.

Tool changes preserve the annotation display nodes and cancel the unfinished pointer interaction, including its ink checkpoints. Released object transforms remain projected until local data takes over, including failed writes retained for retry. The editor supplies committed object intent with its queue revision so a later undo/redo cannot be hidden when the local query skips an intermediate position. This projection is scoped to the mounted edit layer and does not wait for cloud synchronization.

Highlighter coverage deposits a coat only in the area newly entered by the moving nib. Adjacent samples share the prior contact footprint, while retracing or crossing after leaving an area adds another coat. SVG display, hit testing and PDF export consume the same coverage geometry. Geometry uses the PDF page's intrinsic aspect ratio; zoom-dependent DOM rounding must not reshape saved ink. This changes rendering of retraced existing highlighters without rewriting their point data or changing the annotation schema; older deployed clients retain their previous single-coat rendering until updated.


Reading-mode page-turn taps divide the visible viewport into equal horizontal thirds: previous page on the left, chrome in the center, and next page on the right. This uses viewport width without a pixel cap and retains the existing editing and zoom restrictions. An object transform owns its pointer sequence: adding a second finger continues transforming that object rather than starting viewport navigation. Blank-page two-finger navigation still interrupts unfinished ink. Page spacing belongs to the pager layout, not foreground gutter overlays that can obscure the score during pinch previews.
