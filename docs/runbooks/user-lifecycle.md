# 用户与成员关系生命周期

对应 Issue #97 工作包 A；产品入口为首页“用户设置”，成员管理从本人管理员成员关系进入。

## 身份验证与状态

- 删除开始时记录当前用户、原会话、既有关联登录方式与十分钟期限。必须通过邮箱密码或原有 Google/微信完成一次新的认证会话，提交绑定显示用户 ID 的确认。
- 删除事务先固定共享署名、撤销所有产品会话及活跃成员关系；任一云盘只剩该管理员时整个事务回滚。先在对应云盘授予另一成员管理员，再执行删除。
- 删除后原身份可生成受限的恢复验证会话；普通会话接口不显示它，所有云盘权限及批注提交事务拒绝它。只有删除时的登录方式能在三十天内确认恢复。
- 恢复删除状态时同时恢复本次删除终止的成员关系，角色为普通成员，不恢复共享编辑授权。以前退出/移除的关系保持原状态。恢复后重新登录；其他方式不能手工合并或接管该用户。
- 用户删除和恢复会撤销所有当时的会话。响应丢失时重新登录并查询状态，不重复延长保留期；旧删除 ID 不能恢复后一次删除。
- 成员移除、恢复、升降管理员都核对成员修订号；相同操作重试无副作用。普通云盘已移除身份不能通过旧访客 cookie 自动退回访客权限，公开体验例外仍保留。

## 本机数据与到期清理

用户删除只断开本机当前/最后身份指针，不删除原用户下的草稿。成员退出/移除不清除离线副本或 outbox。A/B 切换继续由 owner 隔离；同一用户恢复后，旧 opId 可以重试，冲突仍通过原 OCC 处理。普通云盘到期后的成员关系属于新加入，旧个人层的草稿不会自动迁移到新层。

小时任务每次处理至多 100 个到期用户及 100 个已移除普通成员关系：用户清理通过 FK 删除认证身份、会话、个人层及用户偏好；共享对象与同步历史保留，用户外键置空。成员清理保留最终署名，删除其个人层和偏好再删除关系。公开体验的成员移除不触发个人层清理。重试操作无越权；每次删除重新检查状态，恢复与清理由数据库序列化。过期验证数据也被清理，诊断不包含正文或凭据。

## 发布与恢复验收

1. 运行 `npm run check:full`，核对 migration `0014_user_and_membership_lifecycle.sql`，尤其同步历史表的复制、原 sequence 保留及 actor 外键由级联删除改为置空。
2. 生产迁移前记录表行数、最大同步序列及索引/外键状态，按既定 D1 备份流程保留可恢复点；不导出身份或批注正文到诊断。
3. 代码和迁移一起发布，小时任务同时包含文件及生命周期清理。核对每次任务失败报警；若积压持续增长，先调查失败原因再增加处理额度。
4. 在测试用户/云盘验证：邮箱、Google、微信各自重新认证→删除→恢复→再次删除；另一用户不能确认该删除；跨云盘最后管理员阻止；A/B 切换不显示/同步另一人的草稿。
5. 测试预览成员移除后的个人层保留；普通成员移除时拦截提交、恢复后同 opId 重试；模拟清理失败后再次执行及清理/恢复竞争。
6. 生产到期删除是不可逆的数据操作，不能仅回退 Worker 来恢复数据。紧急停清理需暂停部署环境定时触发或发布禁用清理的修复，再核对 D1 恢复点与受影响用户范围；不得假称三十天以后仍可产品内恢复。

本地门禁与模拟 OAuth 不能替代生产提供方配置及真实设备证据。上线后另核对 Google/微信回调、会话撤销和本机草稿恢复；不要在验收日志中保存 OTP、cookie、OAuth code 或 token。
