# #211 邀请进入与 Android 安装验证

## 复现与根因

基线：`9411371`（PR #207）。使用测试夹具生成的有效邀请；不记录实际凭证、含 fragment 的网址或输入框截图。

1. 已打开首页时，通过站内导航或同文档 hash 导航打开邀请。原实现只在 HomeContent 的 useState initializer 读取 fragment；组件未重新挂载时，linkInvite 保持 null，自动准入不执行。路由回归在修复前失败，修复后自动进入目标云盘。
2. 曾登录过的浏览器，在在线会话已确认为未登录时打开有效邀请。本机记住的用户让首页进入 LocalEntry；即使绕过首页，本机用户仍使云盘目录走该用户的本机路径。修复让明确的邀请访客准入进入独立访客空间，保留原用户数据，后续登录仍能恢复原归属。会话未确认或网络不可达时不把缓存身份当作在线身份。
3. Chromium 真实路由暴露出 `navigate()` 清理 URL 尚未提交、准入请求已发出的时序：原来仅调用 navigate 随即进入准入。现在等待下一次已清除 fragment 的 location 提交才请求；本地浏览器回归在请求边界检查此条件。
4. Android 原生安装事件原先藏在第二次确认后。现在入口在用户点击调用链中直接消费已保存事件，原生能力可用时突出主按钮；无事件时打开手动说明。取消和失败保留说明，新事件可再次调用；已安装事件和应用窗口模式隐藏引导。

## 针对性自动化

- AppRoutes：有效邀请首次进入、首页已打开再次进入、StrictMode 单次准入、会话检查后继续、记住旧用户的未登录访客、登录非成员补显示名、已有成员直接进入、网络失败保留邀请码重试、真正畸形链接手动修正。
- LocalWorkspace：显式访客准入切换归属，旧用户空间不再是活动空间，重新登录可恢复原归属；持久化中途取消会回滚归属和 epoch。
- InstallProvider：点击直接调用原生 prompt、一次性消费、取消、失败后新事件、appinstalled、已安装模式、无原生事件的手动说明、微信外部浏览器说明、Android 权限和结果文案。
- Chromium + 本地真实 Worker/D1：新页访客、同文档 hash 导航、已有成员、登录非成员补显示名；准入请求发送前 fragment 已清理，准入只发生一次，最终可见目标云盘乐谱。测试邀请码仅驻留夹具内存和请求，不输出日志或截图。

运行命令与结果以 PR 中本次执行记录为准。

## 实体设备与线上边界

本次自动化不构成生产复现或实体 Android 验收。尚需在实际设备记录系统版本、浏览器版本、是否收到原生事件，以及安装后从桌面图标打开合谱范围内页面的窗口形态。微信“在浏览器中打开”是否保留原始邀请 fragment 也需真机核实；如果外部 App 在交接前丢弃 fragment，网站无法恢复已丢失的凭证，不能将此推断成邀请码失效。

Android 检查项：有事件时一次点击打开原生窗口；取消/失败后手动步骤可用；无事件不出现可调用原生按钮；微信使用外部浏览器；检查当前浏览器的桌面快捷方式权限（手机提供时）；从图标打开应用范围内页面，外部链接另开浏览器不算失败。安装成功与所需乐谱离线副本就绪分别验收。

安装事件生命周期依据：[Google 自定义安装体验](https://web.dev/articles/customize-install)、[PWA 安装提示](https://web.dev/learn/pwa/installation-prompt)。文档明确 prompt 只能消费一次，新事件才能再次调用；网页无法强制制造浏览器未提供的安装能力。
